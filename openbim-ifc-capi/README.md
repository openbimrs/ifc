# openbim-ifc-capi

Versioned C ABI for [`openbim-ifc`](../openbim-ifc): read, edit and write
IFC STEP files from C, C++ or anything with a C FFI. Built as a static and
a shared library; the header is `include/openbim_ifc.h`, generated by
cbindgen and checked for drift in the gate.

The conventions follow Axiolid's C ABI (its ADR 0040), so a host can load
both the same way.

## Protocol

- **Versioned symbols.** Every export is `openbim_ifc_v0_1_*`;
  `openbim_ifc_v0_1_version` reports the ABI and crate versions separately.
- **Opaque handles.** An `OpenbimIfcModel` is a non-zero integer, never a
  pointer. Zero, stale and destroyed handles return `INVALID_HANDLE`.
  Destroy each model once with `openbim_ifc_v0_1_model_destroy`.
- **Caller-owned buffers.** No Rust allocation crosses the ABI. Every
  output that varies in size takes `(buffer, capacity, out_required)`:
  `out_required` is always written; a short buffer returns
  `BUFFER_TOO_SMALL` and is left untouched. Call once with `NULL, 0` to
  size, allocate, call again.
- **Statuses, never crashes.** Nulls, bad UTF-8, malformed input and Rust
  panics all become an `OpenbimIfcStatus`. After a failed call on a model,
  `openbim_ifc_v0_1_last_error_code` / `_message` explain it; the next
  successful call clears them. Error codes (`missing-entity`, ...) match
  the Python and JavaScript bindings.
- **Threads.** Calls on different models run in parallel; calls on the same
  model are serialised.

## Values: tapes

An attribute value is a tree (`(#1,#2)`, `IFCLABEL('x')`), so it crosses
as a **tape**: a flat array of `OpenbimIfcValueNode` in pre-order, plus one
byte buffer holding every string.

| `kind` (`OPENBIM_IFC_KIND_*`) | fields used |
| --- | --- |
| `NULL` `$`, `DERIVED` `*`, `UNKNOWN` `.U.` | -- |
| `BOOL` | `int_value` (0/1) |
| `INTEGER` | `int_value` |
| `REAL` | `real_value` (finite) |
| `TEXT`, `BINARY`, `ENUM` | `str_offset`, `str_len` |
| `REF` | `int_value` = entity id |
| `LIST` | `child_count`; children follow |
| `TYPED` | `str_offset`/`str_len` = type name; one child follows |

`LIST(REF 1, TYPED "IFCLABEL" (TEXT "x"))` is four nodes. Unused fields
must be zero; a malformed tape is `INVALID_VALUE` and changes nothing.

## Build and test

```sh
cargo build -p openbim-ifc-capi --release      # libopenbim_ifc_capi.{a,so}
openbim-ifc-capi/scripts/check-c.sh            # C11 and C++17 smoke tests
UPDATE_HEADER=1 cargo test -p openbim-ifc-capi --test header   # regenerate
```

Static linking on Linux also needs `-lpthread -ldl -lm`.

### Faster reading (opt-in)

```sh
cargo build -p openbim-ifc-capi --release --features rusty_alloc
```

Uses the pure-Rust rusty_alloc allocator for the library's own memory:
reading STEP into a model takes 18-35% less CPU time on seven real IFC
files, at 1-7% less peak memory (#49). The host's `malloc` is not
replaced, and no Rust allocation crosses the ABI. Off by default because a
global allocator is a build-time choice; the version is pinned exactly.

## Not yet

No CMake package and no prebuilt binaries; a host builds the library with
cargo. Domain views (properties, quantities, geometry) are not bound.
